# Textes du formulaire kit — 13 octobre 2026

Sam demande moins de petites phrases et de répétitions dans la création de kit.
Chaque papier conserve son nom et son contrôle de quantité ; le rappel
base/à préparer est retiré de la ligne. Une collection complète n’affiche plus
le compteur répété ni la consigne Total atteint. Une répartition incomplète ou
excédentaire garde un état local concis ; les erreurs de validation sont conservées.
Le format C garde sa règle courte : cinq feuilles, au moins une par papier.
Le résumé indique directement les quantités à préparer, avec le doublement si
sélectionné. Les explications des tarifs, matériaux et suppléments sont retirées,
le ruban automatique est simplement nommé et l’option devient Doubler les papiers.
Les avertissements d’édition, les erreurs et les règles métier restent conservés.

Validation Chromium sans enregistrement : format A, deux collections, contrôle
à trois feuilles, retrait puis ajout (message incomplet puis disparition),
doublement (quantités de saisie inchangées, résumé à dix feuilles), mobile sans
débordement et aucune erreur navigateur. `npm run check` : 93 backend, 72 frontend
et build réussis ; Docker et contrôle du diff réussis. Aucun audit supplémentaire.
Changement local sur codex/petits-fix, pas encore committé.

La date de commande est ensuite placée sur une ligne entière sous le paiement.
Le calendrier déplié occupe aussi toute la largeur du formulaire principal, sans
la limite habituelle de 440 px. Mesures Chromium du champ et du calendrier,
mobile sans débordement, suite complète et build réussis.
